# 실험: few-shot COA 생성 품질 (2026-10-19)

**질문**: pseudo-GT 예시(few-shot)와 교범을 주면 생성 모델이 쓸 만한 COA를 만드는가. 시뮬레이터 없이 먼저 봅니다.

| 조건 | 생성 모델이 받는 것 |
|---|---|
| Z | 상황 + 명령 규칙(system) |
| D | Z + 교범 1·2·3 |
| F | Z + pseudo-GT 예시 3건 (같은 전투 제외, leave-one-out) |
| DF | Z + 교범 + 예시 |

50건 각각을 네 조건으로 생성했습니다. 프롬프트는 [`pseudo_coa/generate/prompt.py`](../../pseudo_coa/generate/prompt.py)와 글자 단위로 같습니다(`python -m pseudo_coa prompt <id> --cond <조건>`으로 볼 수 있다).

## 다시 돌리기

few-shot으로 쓸 만한 COA가 나오는지 시뮬레이터 없이 먼저 본 실험입니다. 50건 모두를 leave-one-out으로 돌렸고, 조건은 Z / D / F / DF 네 가지입니다.

```bash
python3 experiments/2026-10-19_fewshot/run_gen.py --model claude-sonnet-5-5 --workers 4   # 200건 생성 → results/gen/<cond>/<id>.json
python3 experiments/2026-10-19_fewshot/score.py                                           # 규칙 검사 + GT 구조 일치 → results/scores.jsonl
python3 experiments/2026-10-19_fewshot/judge.py --model claude-opus-5-5 --workers 4       # LLM 블라인드 심사 (GT 포함) → results/judge/
python3 experiments/2026-10-19_fewshot/report.py                                          # → results/REPORT.md
```

평가는 세 층입니다.

1. **규칙 검사**: `pseudo_coa.validate` 오류가 0인 비율. 시뮬레이터에 바로 넣을 수 있는가를 봅니다.
2. **pseudo-GT와의 구조 일치**: 부대별 배치 거리(km), 주력·예비 구성 일치(Jaccard), 예비 투입 조건 일치, 핵심 지형·과업 목표 지형 일치, 임무 동사 일치. GT는 역사적 재구성이지 최적해가 아닙니다. 그래서 이 값은 "실제 지휘관과 얼마나 비슷하게 판단했나"를 뜻하고 "얼마나 좋은가"를 뜻하지 않습니다.
3. **LLM 심사**: 심사 모델은 situation과 order 하나만 보고 다섯 항목(임무 부합, 지형 활용, 적 대응, 전투력 운용, 협조·실행성)을 1~5점으로, 전체를 1~10점으로 매깁니다. GT order도 같은 프롬프트로 출처를 숨기고 채점해 기준선으로 씁니다.

최종 판단은 시뮬레이션입니다. 같은 scenario에서 생성 COA와 GT COA를 돌려 결과(`history.outcome_metrics` 꼴)를 비교합니다.

## 결과

2026-10-19 실행. 생성 모델은 claude-sonnet-5-5(effort medium), 심사 모델은 claude-opus-5-5(effort medium)입니다. 50건 × 4조건 = 생성 200건, 심사 250건(GT 50건 포함)입니다. 비용은 생성 $44, 심사 $35입니다. 전체 표는 [`results/REPORT.md`](results/REPORT.md)에 있고, 생성된 COA는 `results/gen/<조건>/<id>.json`, 심사 결과는 `results/judge/<조건>/<id>.json`에 있습니다. 교범은 교범 1·2·3(동사 정의, 명령 구성 요소, 임무 유형별 조항)이 들어간 판입니다.

| 지표 | Z (규칙만) | D (+교범) | F (+예시) | DF (+교범+예시) | GT |
|---|---|---|---|---|---|
| 검사 통과(오류 0) | 90% | **74%** | 90% | 92% | 100% |
| 심사 overall (1~10) | 5.18 | 5.28 | **5.52** | 5.48 | 5.36 |
| 예비 투입 조건 대상이 GT와 같음 | 15% | 19% | **34%** | 30% | — |
| 과업 동사 집합 일치 (J) | 0.36 | 0.37 | **0.51** | 0.50 | — |
| 과업 목표 지형 일치 (J) | 0.31 | 0.37 | 0.36 | **0.44** | — |
| 부대 배치 거리, GT 대비 (km, 기준선 1.73) | 1.63 | 1.63 | 1.56 | 1.53 | 0 |

같은 사례끼리 짝지은 심사 overall 차이(95% 부트스트랩 구간)는 다음과 같습니다.

| 비교 | 차이 |
|---|---|
| F − Z | +0.34 [+0.18, +0.50] |
| DF − Z | +0.30 [+0.16, +0.44] |
| D − Z | +0.10 [−0.08, +0.26] |
| DF − F | −0.04 [−0.22, +0.14] |
| F − GT | +0.16 [−0.06, +0.40] |

**읽는 법**

1. **pseudo-GT 예시(few-shot)는 효과가 있습니다.** 예시를 주면 심사 점수가 0.3점 오르고 GT와 같은 수준이 됩니다(F가 GT보다 높음 16건, 같음 25건, 낮음 9건). 조건 쓰는 법, 동사 선택, 예비 투입 대상도 GT에 가까워집니다.
2. **지금의 교범 묶음은 효과가 거의 없습니다.** 교범만 주면(D) 검사 통과율이 오히려 떨어집니다. 실패 13건 중 11건은 `concept.main_effort`에 group id 대신 문장("G1이 주력이다…")을 쓴 형식 오류입니다. 예시가 있으면(DF) 이 오류는 사라지지만, 예시만 준 F보다 나아지지도 않습니다. 교범 3이 검색으로 고른 것이라 품질이 낮고, 방책 수립 절차(상대 전투력, 시간·거리, 결심점)가 빠진 것이 원인으로 보입니다.
3. **배치 판단은 실제 지휘관과 여전히 다릅니다.** 부대별 배치 거리가 모든 조건에서 1.5~1.6km입니다. 모든 부대를 GT 배치 중심에 둔 기준선(1.73km)보다 조금 나을 뿐입니다. 형식과 관행은 예시에서 배우지만, 어디에 무엇을 둘지는 잘 옮겨 오지 못합니다.
4. **심사 점수로 "좋은 COA"를 말할 수는 없습니다.** GT의 심사 점수는 실제 결과와 반대로 움직였습니다(성공 5.16, 부분 성공 5.53, 실패 5.60). 심사는 교범적 완성도를 보고 결과를 예측하지 않습니다. 품질의 최종 판단은 시뮬레이션 결과로 합니다.
