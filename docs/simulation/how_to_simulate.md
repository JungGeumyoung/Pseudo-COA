# 시뮬레이션 방법

시뮬레이터가 사례(`sim-input` 출력)를 **무엇을, 어떤 순서로, 어떻게 해석해 돌리는가**를 정합니다. 필드 정의는 [JSON 필드 사전](../reference/json_fields.md)에 있고, 여기서는 그 필드들이 시뮬레이션에서 무엇이 되는지만 다룹니다.

이 문서는 데이터를 만든 쪽이 정한 의미이고, pysc2에서 어떻게 구현하는지는 시뮬레이션 팀이 정합니다. 데이터 쪽 정의가 비어 있어 구현 팀이 정해야 하는 것은 **[결정 필요]** 로 표시하고 [정해야 할 것들](../simulation/decisions_needed.md)에 모았습니다.

## 1. 원칙: 결과는 시뮬레이터가 낸다

데이터에는 **결정만** 들어 있습니다. 전투가 어떻게 끝났는지는 들어 있지 않습니다.

| 시뮬레이터에 들어가는 것 | 들어가지 않는 것 (`history`에만 있음) |
|---|---|
| 양측의 처음 배치 | 고지의 피탈·탈환, 격퇴, 돈좌, 철수 |
| 양측의 계획: 공격 개시 시각, 축선, 목표, 예비 위치 | 실제 결심 시각, 실제 증원 투입 시각 |
| 전투력에 반응하는 규칙: 예비 투입, 역습, 재공격, 철수 | 손실, 결과 시각 |
| 전투와 무관한 외생 사건: 야간, 안개, 계획된 폭파, 항공 가능 시간 | 요청에 따른 항공 폭격 같은 반응의 결과 |

따라서 시뮬레이터가 `history`를 읽으면 안 됩니다. `python -m pseudo_coa sim-input <id>`(파이썬에서는 `load_case(id).sim_input(order)`)가 `history.json`을 뺀 입력 하나(`input` + `order` + `scenario` + 축척)를 만듭니다.

## 2. 읽는 순서

| 단계 | 읽는 필드 | 시뮬레이터가 할 일 |
|---|---|---|
| 1. 맵 | `input.terrain` (`features`, `routes`, `impassable`), `input.area_of_operations.boundaries` | 200×200 캔버스를 맵으로 만듭니다. 고지(`elevation_m`), 통과 불가 다각형, 도로 |
| 2. 아군 배치 | `order.task_organization.groups` → `input.available_forces`, `order.execution.tasks[].deploy` | 그룹마다 유닛을 만들고(§3) `deploy.xy`, `elements[]` 위치에 놓습니다. `preparation`으로 방호 계수를 줍니다 |
| 3. 적 배치 | `input.enemy_forces[].position`, `scenario.hidden_enemy[].position` | 적 유닛을 처음 위치에 놓습니다 |
| 4. 인접·상급 부대 | `input.higher_context.adjacent_units`, `higher_rules` | 규칙에 나오는 인접 부대를 `xy`에 둡니다 **[결정 필요: 처음부터 맵에 둘지, 규칙이 발동할 때 등장시킬지]** |
| 5. 규칙 등록 | 아군 `tasks[].items[]`, `concept.reserve`, `coordinating.time_plan`, 적 `scenario.enemy_plan`, 상급 `higher_rules` | §5의 실행기에 등록합니다 |
| 6. 외생 사건 등록 | `scenario.exogenous` | §6 |
| 7. 진행 | `scenario.start_t`부터 `start_t + horizon_h`까지 | 매 판정 주기마다 사건을 판정하고 행동을 진행합니다 |
| 8. 종료와 기록 | `scenario.stop_conditions`, 끝 시각 | §7의 결과 지표를 남깁니다 |

### 좌표와 시간 환산
- **공간**: [`sim_unit_table.json`](../../sim_unit_table.json)의 기본값은 캔버스 1단위 = SC2 맵 1칸입니다. 1단위가 몇 m인지는 `meta.geo.scale_m_per_unit`(50건 모두 100m)를 따릅니다. 데이터는 북쪽 +y, 원점 왼쪽 아래입니다. SC2 좌표계와 y축 방향이 같은지 확인해야 합니다.
- **시간**: `t`는 D일 00:00부터의 시간입니다. 기본 제안은 SC2 게임 1분 = 실제 60분입니다. 이동 속도는 보병 약 3km/h, 차량 약 15km/h가 되도록 계수로 맞춥니다.
- **좌표의 정확도**: 지형지물 741개 가운데 703개가 `estimated: true`(서술로 추정)입니다. 아틀라스로 잰 사례는 3건입니다(`meta.geo.source = "atlas+text"`). 상대 위치는 믿을 수 있지만 수백 m 단위의 정밀도는 기대하지 않습니다.

## 3. 부대를 유닛으로 바꾸기

규모를 유닛 수로 바꾸는 규칙은 **[`sim_unit_table.json`](../../sim_unit_table.json) 한 곳에만** 있습니다. 데이터에는 군사적 규모(`echelon`, `type`, `modifier`, `strength_pct`)만 있습니다. 50건이 같은 표를 쓰므로, 보정할 때는 표만 고치면 됩니다. 이 표도 아직 보정 전 초안입니다.

- 기준: 유닛 1개 = 보병 소대 1개(약 40명).
- infantry: 중대 = 보병 3 + 화기 1 = 4, 대대 = 15, 연대 = 48.
- SC2 매핑 제안: 보병 Marine, 화기·대전차 Marauder, 전차 SiegeTank(전차 모드), 정찰 Reaper, 공병 SCV. 포병·박격포·항공은 유닛이 아니라 **화력 이벤트**(지역 피해)로 둡니다.
- `modifier "+"/"-"`: 전투편성 `composition[].part`에 적힌 배속·분리를 더하거나 뺍니다. "-"인데 분리 부대가 적혀 있지 않으면 예하 1개 부대를 뺍니다.
- `strength_pct`: 보병·화기 수에 곱하고 반올림합니다(최소 1).
- 사단 이상은 유닛으로 만들지 않습니다. 데이터도 사단은 연대로 나눠 적었습니다.
- 초기 계수 제안(같은 파일): 국가·연도별 화력 계수, `preparation`별 피해 감소(none 0, hasty 0.15, deliberate 0.3, fortified 0.5), 고지 보너스, 야간·안개 시야 감소.

### 예: 그룹 G1 = `[{force: F1}, {force: F3, part: "제11중대"}]`
F1 보병 대대 = 15, 그리고 F3의 제11중대 = 보병 중대 4. 합계 19유닛입니다. 같은 F3에서 `part: "-제11중대"`인 G3는 15 − 4 = 11유닛입니다.

## 4. 사건 판정

판정 주기의 기본 제안은 게임 1초입니다(`sim_unit_table.json`의 `scale_defaults.trigger_poll`).

| type | 참이 되는 때 |
|---|---|
| `time_elapsed` | 현재 t ≥ `value` |
| `losses_exceed` | (처음 유닛 가치 − 현재 유닛 가치) / 처음 유닛 가치 > `fraction`. `group`의 처음 값은 시뮬레이션 시작 때 값입니다. 유닛 가치는 유닛 표의 환산을 따릅니다 |
| `strength_in_area` | `ref` 영역 안에 있는 `side` 진영 유닛의 환산값 합이 `min_echelon` 기준 이상. 기준은 소대 1, 중대 4, 대대 15, 연대 48. `group`이 있으면 그 부대의 유닛만 셉니다 |

- **영역**: `ref`가 다각형(통제수단 `xy` 3개 이상, `polygon`이 있는 지형)이면 그 안입니다. 점(고지 `xy`, 통제수단 점)이면 반경 500m(5단위) 원입니다. 선이면 **[결정 필요]**.
- **side**: 반응 조건의 `side`는 진영을 그대로 가리킵니다. `enemy`는 적입니다. 아군 규칙이든 적 규칙이든 같습니다. 적 규칙에 `side: "friendly"`가 있으면 "아군이 그 지역에 있음"입니다.
- **and**: 바깥 사건과 `and` 안의 사건이 모두 참이어야 참입니다. 바깥 사건에 `group`·`ref`가 없으면 바깥은 묶음일 뿐이고 `and` 안의 사건만 봅니다.
- **유지**: 한 번 참이 된 조건으로 시작한 행동은 조건이 다시 거짓이 되어도 계속합니다(래치). 같은 규칙이 두 번 발동하지는 않습니다. **[결정 필요: 다르게 구현하면 데이터 쪽에 알려 주십시오]**
- **group이 없는 losses_exceed**: `stop_conditions`에만 있습니다(5건). `side`만 있으면 그 진영 전체 유닛의 누적 손실입니다.

## 5. 행동 규칙의 실행

아군 과업, 적 계획, 상급 규칙은 같은 실행기로 처리할 수 있습니다. 부대마다 항목 목록이 있고, 각 항목은 시작 방식 하나를 가집니다.

| 아군 `timing` | 적 `timing` | 상급 `timing` | 시작 |
|---|---|---|---|
| 즉시 | — | — | 시뮬레이션 시작 때 |
| — | 계획 | 계획 | `start.value`(적) 또는 `trigger.value`(상급) 시각 |
| 이어서 | 이어서 | — | 같은 목록에서 바로 앞 항목이 **끝났을 때** |
| 명에 의해 | 조건 | 조건 | `trigger`가 참이 될 때 |

- **끝났는지의 판정**: 탈취·점령·확보·공격은 목표를 장악했을 때, 초월은 통과지점을 지났을 때, 철수·이탈은 목적지에 도착했을 때입니다. 고수·방어·경계·화력지원처럼 끝이 없는 과업 뒤에는 '이어서'가 오지 않는 게 보통입니다. 끝이 없는 과업의 끝 판정은 **[결정 필요]**.
- **장악**: 목표 영역 안에 우리 편이 있고 적이 없거나 기준 미만인 상태. 기준은 **[결정 필요]**.
- **같은 부대에서 겹칠 때**: '명에 의해' 항목이 발동하면 그 부대의 앞선 항목을 멈추고 새 항목을 실행합니다(예: 예비가 예비진지 점령을 마치고 역습). **[결정 필요]**
- **`repeat {max, interval_h}`**: 같은 행동을 `interval_h` 간격으로 되풀이합니다. max가 첫 실행을 포함하는지는 **[결정 필요]**. 데이터를 만든 의도는 "최대 max번 공격"입니다.
- **`higher_rules[].delay_h`**: 조건이 참이 된 뒤 그 시간만큼 지나서 시작합니다(1건).
- **'계획'으로 정한 행동은 결과와 상관없이 그 시각에 시작합니다.** 앞선 공격이 성공했든 실패했든 그렇습니다. 반응해야 하는 행동은 '조건'으로 들어 있습니다.

### 동사·mode → SC2 행동

데이터의 어휘는 교범 과업입니다. 이것을 SC2 명령으로 바꾸는 표는 시뮬레이션 팀이 정합니다. 아래는 데이터 쪽 의도를 적은 출발점입니다.

**아군 과업 동사**

| 동사 | 데이터가 뜻하는 것 | SC2 구현 제안 |
|---|---|---|
| 점령 | 적이 없는 지형에 들어가 진지를 차립니다 | `objective`로 이동하고 정지·방어 |
| 고수 | 손실이 커도 그 지형을 지킵니다. 물러나지 않습니다 | 정지·방어. 후퇴 규칙 없음 |
| 방어 | `area`를 지킵니다. 진지 안에서 기동 가능 | 영역 안에서 교전(attack-move 반경 제한) |
| 탈취·공격 | 적이 있는 지형을 빼앗습니다 | `objective`로 attack-move |
| 확보 | 지형을 쥐고 적의 사용을 막습니다 | 탈취와 같고, 도착 뒤 방어 |
| 역습 | `route`를 따라 `objective`를 되찾습니다 | route 경유점으로 attack-move |
| 경계·차장 | `area`에서 조기 경보, 접촉 뒤 지연 | 영역 안에서 정찰·교전 |
| 차단·저지 | `line`/`area`에서 적의 통과를 막습니다 | 선 위에 배치하고 방어 |
| 지연 | `lines`를 차례로 지키다가 `disengage` 조건에서 다음 선으로 | 선별 방어, 손실 조건에서 다음 선으로 이동 |
| 철수·이탈 | `destination`으로 물러납니다 | move(교전 회피) |
| 초월 | `passed_group`을 `passage_point`로 지나 앞으로 나갑니다 | 통과지점 경유 이동 |
| 화력지원·화력공격 | `target_ref`에 화력을 줍니다 | 화력 이벤트 |
| 엄호·후속지원·후속인수 | 다른 group을 따라가며 지원하거나 이어받습니다 | 대상 group 추종 |
| 격멸·격퇴·고착·견제 등 | `target_group`/`target_ref`에 대한 공격 | 대상에 attack |

**적 mode**: attack, counterattack(objective로 attack-move) / infiltrate(교전을 피하며 이동한 뒤 공격) / fix(그 자리에서 교전해 아군을 묶음) / hold(현 위치 방어) / bombard(화력 이벤트) / reinforce(objective 방향으로 이동해 합류) / withdraw(물러남) / pursue(물러나는 적을 따라감).

실제로 쓰인 빈도는 [열거값 사전](../reference/vocabulary.md)을 봅니다. 25개 동사가 쓰였고, 방어·고수·점령·탈취·역습·화력지원이 대부분입니다.

## 6. 외생 사건

`scenario.exogenous[]`는 전투 결과와 무관하게 정해진 시각에 일어납니다. `t`부터 `duration_h` 동안 효과가 있습니다.

| kind | 효과 제안 (`sim_unit_table.json` `coefficients_initial`) |
|---|---|
| night | 시야 −50%, 항공 화력 불가 |
| dawn | 여명. 보통 1시간. 효과 없음 또는 시야 소폭 감소 |
| fog | 시야 −70%, 포병·항공 화력 불가. `ref`가 있으면 그 지역만 |
| air_window | 이 시간대에만 항공 화력 이벤트 가능 |
| flood | `ref`의 `impassable`(active = 구간 중 발생)을 켭니다. `gap_at`만 통과 |
| weather, other | `note`를 보고 정합니다 **[결정 필요]** |

## 7. 종료와 평가

- **끝 시각**: `start_t + horizon_h`.
- **조기 종료**: `stop_conditions[]` 가운데 하나라도 참이면 끝냅니다.
- **남겨야 할 결과 지표** (`history.outcome_metrics`와 같은 꼴로 남기면 비교가 쉽습니다):
  - 끝 시각에 아군이 쥔 지형 id 목록 → `terrain_held_at_horizon`과 비교
  - group별·진영별 누적 손실 비율 → `friendly_loss_pct`, `enemy_loss_pct`(약 40건에 있음)
  - 주요 사건 시각(지형 장악·상실, 규칙 발동) → `key_times[]{t, ref}`와 비교
- **평가 셋**:
  1. pseudo-GT `order`(`cases/<id>/coa.json` 그대로) → 실제 결과(`history`)에 가깝습니까. 시뮬레이터 보정용
  2. 새 COA `order` → pseudo-GT 결과보다 낫습니까, 나쁩니까
  3. 같은 사례, 같은 시드로 여러 번 → 결과의 분산
- 보정 목표(`sim_unit_table.json` `calibration_targets`): pseudo-GT로 실제 고지 유지 여부와 손실 비율이 재현될 것, 준비된 진지를 정면으로 공격하면 국지적으로 3:1 이상일 때만 탈취될 것, 과업을 전부 '공격'으로 바꾸면 결과가 나빠질 것.
- [`cases/README.md`](../../cases/README.md)에서 `outcome_free`가 '아니오'인 20건은 시나리오에 결과가 섞였을 수 있습니다. 보정 기준선에서는 우선 빼는 것을 권합니다.

## 8. 새 COA를 넣을 때

새로 생성한 COA는 **`order` 블록 하나**입니다. `input`, `scenario`는 사례 것을 그대로 씁니다.

```
python -m pseudo_coa validate kb2_023 new_order.json                # 오류가 없어야 한다
python -m pseudo_coa sim-input kb2_023 --coa new_order.json -o sim_input.json
```
