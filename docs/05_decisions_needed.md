# 05. 정해야 할 것들

데이터만으로는 정해지지 않아 **시뮬레이션 팀이 정해야 하는 것**이다. 정한 내용은 이 표의 '결정' 열에 적어 데이터 쪽과 공유해 주면 된다. 데이터 쪽 정의를 바꿔야 하는 항목은 그렇게 표시했다.

| # | 주제 | 질문 | 데이터 쪽 제안 | 관련 문서 | 결정 |
|---|---|---|---|---|---|
| Q1 | 동사 매핑 | 과업 동사 25개(실사용)와 적 mode 9개를 SC2 행동으로 어떻게 바꾸나. 특히 고수·방어, 차단·저지, 경계·차장의 차이 | [02 §5](02_how_to_simulate.md#동사mode--sc2-행동) 표 | 02 §5, 04 | |
| Q2 | '이어서' 완료 | 고수·방어·화력지원처럼 끝이 없는 과업의 끝 판정. bombard 뒤의 '이어서'(적 포병)는 언제 시작하나 | 끝이 없는 과업은 끝나지 않음. bombard는 다음 '계획' 시각이나 일정 시간 뒤 | 02 §5 | |
| Q3 | 장악 판정 | 목표를 "장악했다"의 기준(영역 안 적 유닛 0? 기준 미만?) | 영역 안 적 환산값 < 소대(1) 이고 아군 ≥ 소대 | 02 §5 | |
| Q4 | 영역 | `strength_in_area`의 ref가 점이면 반경 500m. 선(전투지경선, 통제선)이면? | 선에서 250m 띠 | 02 §4 | |
| Q5 | 조건 유지 | 조건으로 시작한 행동을 조건이 거짓이 되면 멈추나(래치 여부). 같은 규칙이 다시 발동하나 | 래치, 1회 발동 | 02 §4 | |
| Q6 | 항목 겹침 | 같은 group에서 '명에 의해' 항목이 발동하면 진행 중인 항목은 멈추나 | 멈추고 새 항목 실행 | 02 §5 | |
| Q7 | repeat | `repeat.max`가 첫 실행을 포함하나. 각 반복은 같은 축선·목표인가 | 첫 실행 포함, 같은 축선·목표 | 02 §5 | |
| Q8 | 인접 부대 | `higher_rules`에 나오는 인접 부대(`ADJ*`)를 처음부터 맵에 둘지, 발동할 때 `xy`에 생성할지. 규모는 `adjacent_units[].echelon`으로 환산하나 | 발동할 때 생성, echelon으로 환산 | 02 §2 | |
| Q9 | 지도 밖 화력 | 사단 포병·항공처럼 group이 아니고 "지원:"에만 있는 화력. `fire_support.priority_groups/zone_refs`로 화력 이벤트를 어떻게 줄지 | 우선 지원 group 근처 교전지역(`zone_refs`)에 주기적 지역 피해 | 02 §3 | |
| Q10 | 축척 | 1단위(100m) = SC2 1칸이면 맵이 200×200칸이다. 맵 크기, 사거리, 이동 속도 환산 | `sim_unit_table.json scale_defaults` | 02 §2 | |
| Q11 | 시간 | 게임 1분 = 실제 60분이면 48시간 구간이 게임 48분이다. 판정 주기와 속도 | 위 기본값, 판정 1초 | 02 §2 | |
| Q12 | weather·other | 외생 사건 중 weather·other(15건)의 효과 | note를 보고 사례별로, 기본은 효과 없음 | 02 §6 | |
| Q13 | 진영 전체 손실 | `stop_conditions`의 group 없는 losses_exceed(side만)는 전체 유닛 합의 손실로 보면 되나 | 예 | 02 §4 | |
| Q14 | 결과 지표 | 시뮬레이터가 내야 할 결과 형식. `history.outcome_metrics`와 같은 꼴(끝 시각 장악 지형, 손실률, 주요 시각) | [02 §7](02_how_to_simulate.md#7-종료와-평가) | 02 §7 | |
| Q15 | 보정 셋 | `outcome_free = false`인 20건을 보정 기준선에서 뺄지 | 우선 빼고 30건으로 보정 | [사례 목록](../data/README.md) | |
| Q16 | 데이터 수정 요청 | 구현하다가 데이터 표현이 부족하면(예: 새 조건 type, 과업 동사 추가) | 데이터 쪽에 요청. 스키마를 0.7로 올려 반영 | 01 | |
